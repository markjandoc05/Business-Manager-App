# Local authenticated UAT

The Client App authenticated browser UAT uses an isolated Firebase emulator project:

`demo-bsm-client-app`

The repeatable workflow is:

```bash
npm run test:uat:local
```

The runner dynamically allocates local Auth, Firestore, Storage, and Next.js ports. It does not use or seed the repository's standard Firestore port when that port is occupied. The UAT Next.js process also uses a per-run build directory, so it cannot race with another local Next.js process using `.next`. It writes the generated credentials fixture to:

`/private/tmp/ventale-client-uat-credentials.json`

The fixture is generated by `scripts/uat/seed-emulator.mjs`, is outside the repository, and is created with local-only emulator credentials. It is never committed.

The command verifies the demo project identity, starts Auth/Firestore/Storage emulators with the repository Rules and indexes, seeds the existing UAT fixture, builds and starts a separate local Next.js process in an isolated build directory, and runs the existing authenticated suites:

- `tests/uat/authenticated-smoke.spec.mjs`
- `tests/uat/deal-client-selector.spec.mjs`
- `tests/uat/mobile-responsiveness.spec.mjs`

Platform onboarding remains disabled in this test environment. The Platform onboarding UAT in `tests/uat/workspace-creation.spec.mjs` targets the separate `demo-bsm-console` project and is intentionally not included in the Client App runner.

The browser Firebase emulator endpoints are public local-UAT variables (`NEXT_PUBLIC_FIREBASE_AUTH_EMULATOR_HOST`, `NEXT_PUBLIC_FIRESTORE_EMULATOR_HOST`, and `NEXT_PUBLIC_FIREBASE_STORAGE_EMULATOR_HOST`). In normal development they default to 9099, 8080, and 9199; the local runner supplies its dynamically allocated alternatives.
